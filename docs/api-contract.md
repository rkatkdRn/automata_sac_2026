# API contract (implementation contract)
All errors: `{error:{code,message}}`. Cookie authentication; POST JSON. IDs are strings. All times ISO 8601 Asia/Seoul. Student IDs, real names, emails, Google subject IDs (rehearsal data only), and credential tokens are not returned in participant/public responses. The field `nickname` is the display name: the nickname the participant chose, or the anonymous label when hidden.

## Participant
- POST `/api/session` `{kind:"STUDENT",student_id,name,nickname,consent:true}` → `{participant_id,nickname,kind,needs_nickname,auth_method:"STUDENT_ID",attempts_left}` and a maximum 30-day student session. `student_id` is `NN-NNN` (the hyphen is optional on input); `name` 2–30 characters, no digits. The same `student_id` and `name` (spacing and case ignored) continue the existing record and keep its nickname; a different name is `STUDENT_ID_CONFLICT`. New students' nicknames follow the guest rules and are unique across everyone.
- POST `/api/me/nickname` `{nickname}` → session object. Only for students from the removed Google flow who never chose one (`needs_nickname:true`); set once (`NICKNAME_LOCKED` after), and submissions are refused until then (`NICKNAME_REQUIRED`).
- POST `/api/session` `{kind:"GUEST",nickname,consent:true}` → `{participant_id,nickname,attempts_left,...}` and a maximum 12-hour guest session. Nickname alone never restores another participant.
- POST `/api/session/logout` `{}` → `{ok:true}` (for borrowed phone).
- GET `/api/state` → `{day_no,booth_state,open_now,next_open,attempts_left,max_attempts,mychew_left,participant_id:null|string,nickname:null|string,server_time,privacy_contact,cloud_mode,purged:false,threshold_bp}`.
- POST `/api/submissions` `{request_id,strategy:[5 integers],expected_day_no?:1|2|3}` → `{id,day_no,attempt_no,attempts_left,strategy,win_rate,points,opponents,threshold_bp_used,pass_mode,top_bp,submitted_at,rank_estimate:{rank,of,is_provisional:true},today_count,reward:null|{entitlement_id,code,kind,premium_exhausted,choices,status,choice,claimed_at},nemesis:null|{strategy,lost_lanes},pool_size}`. Same request_id returns identical response. Do not change ID after ambiguous network errors. `rank_estimate` is the place in the whole pool (seeds included, same basis as `top_bp`), `of` the pool size.
- GET `/api/me/submissions` → `{items:[full submission results, newest first]}`; current reward status overrides original status; all operating days returned.
- POST `/api/entitlements/{id}/choice` `{choice:"MYCHEW"|"SESAME"|"ACE"}` → full public reward `{entitlement_id,code,kind,premium_exhausted,choices,status:"ISSUED",choice,claimed_at:null}`. One try per person per day (`max_attempts` 1), and that play decides the snack. Every voucher is 1 MYCHEW; a TOP_CHOICE voucher is MYCHEW **plus** one premium item, so its `choices` are `["SESAME","ACE"]` (BASIC: `["MYCHEW"]`). Issuing reserves the MYCHEW (and one generic premium unit for TOP_CHOICE); choice is persisted before claim, repeated same choice is idempotent, and a selected premium item reserves specific stock, preventing overbooking.
- POST `/api/entitlements/{id}/claim` `{choice:"MYCHEW"|"SESAME"|"ACE"}` → `{status:"CLAIMED",choice,claimed_at,code,entitlement_id}`. Claiming a TOP_CHOICE voucher takes 1 MYCHEW and the chosen premium item from stock.
- GET `/api/scoreboard` → `{recent:[{nickname,submitted_at}],day_no,booth_state,mychew_left,pool_size,today_count,updated_at,version,test_mode}`. Public board hides every strategy and ranking so players cannot copy winners; `today_count` = distinct people who played on the current day. Staff: GET `/api/admin/scoreboard` → the same plus `rankings:[{rank,participant_id,submission_id,nickname,strategy,points,opponents,win_rate,submitted_at}]` (top 10), `cycle:null|[ranking row x3]` (among top 30, held >=60s) and `recent` with `strategy,win_rate`. SSE `board.updated` carries the public form.
- GET `/api/hall?scope=DAY1|DAY2|DAY3|OVERALL` → `{scope,frozen:boolean,frozen_at:null|string,rankings:[]}`.
- GET `/api/events` → SSE events `state.changed` (state JSON), `board.updated` (scoreboard JSON), `heartbeat`. Finite stream closes/reconnects about 25s. Fallback poll 5s.

## Admin
- POST `/api/admin/login` `{pin}` → `{ok:true}`; POST `/api/admin/logout` → `{ok:true}`.
- GET `/api/admin/dashboard` → `{day_no,day:{day_no,date,sessions:[["10:00","13:00"],["14:00","17:00"]],mychew_cap_cum,premium_cap_cum,close_rule,booth_state,ever_opened,frozen_at,cap_override},days:[same day objects],state:participant state without identity,counters:{mychew_used,premium_reserved},inventory:{MYCHEW:n,SESAME:n,ACE:n},pool_size,seed_count,participant_count,submission_count,today_submissions,threshold_bp,threshold_locked,threshold_applied,purged,db_mode}`.
- POST `/api/admin/day` `{day_no}` selects operating day, previous day must not OPEN/PAUSED. POST `/api/admin/day-config` `{day_no,date,sessions,mychew_cap_cum,premium_cap_cum,close_rule,reason}` edits unopened day. All fields required. min_seed=50/max_attempts=3 fixed.
- POST `/api/admin/booth` `{action:"OPEN"|"PAUSE"|"CLOSE"|"REOPEN",reason?}` → dashboard. OPEN resumes PAUSED, first open requires >=50 seeds + threshold applied. REOPEN requires reason; caps remain limits for individual reward issuance, cap auto-stop overridden for that day.
- GET `/api/admin/threshold/suggest` → `{value_bp,percentile:85,pool_size}`.
- POST `/api/admin/threshold` `{mode:"LIVE"|"FIXED",value_bp,source:"MANUAL"|"SUGGESTION",reason}` → `{mode,value_bp}`. Once per day before first open; reject after ever_opened. mode defaults to LIVE. FIXED: the day's play passes if its win rate ≥ value_bp. LIVE: it passes if, at that moment, its position in the whole pool (seeds included, ties in the player's favour) is within the top value_bp/10000. Recommended LIVE 1200 (top 12%) for day 1: with the public board hidden, the simulated pass rate is about the cutoff, rising when strategies leak (word of mouth, Hall of Fame); the target is premium cap ÷ 마이쮸 cap ≈ 21%, so later days are rescaled from the observed rate. Existing history rows migrate as FIXED.
- GET `/api/admin/claims` → `{items:[{id,submission_id,participant_id,nickname,day_no,code,kind,premium_exhausted,choice,status,issued_at,claimed_at}],counts:{ISSUED:n,CLAIMED:n,VOID:n},by_item:{MYCHEW:n,SESAME:n,ACE:n}}` current day. Status filter optional `?status=ISSUED`.
- POST `/api/admin/entitlements/{id}/void` `{reason,return_stock:false}` → `{ok:true}`. return_stock true only physically returned CLAIMED item.
- GET `/api/admin/submissions?day=1|2|3|9|ALL` (default current day) → `{day_no,items:[{id,day_no,attempt_no,participant_id,nickname,kind,strategy,points,opponents,win_rate,top_bp,submitted_at,entitlement:null|{id,code,kind,choice,status,issued_at,claimed_at,premium_exhausted}}]}` newest first, seeds excluded. win_rate is the value at submission.
- POST `/api/admin/submissions/{id}/snack` `{kind:null|"BASIC"|"TOP_CHOICE",choice:null|item,status:"ISSUED"|"CLAIMED"|"VOID",reason,return_stock:false}` → `{ok:true}`. Allowed any time, no cap/stock checks. kind null deletes the voucher; a play without one gets a new code. BASIC allows only MYCHEW; TOP_CHOICE only SESAME/ACE (it always includes the MYCHEW). Real days write `ADMIN_ADJUST` ledger rows: becoming CLAIMED takes the voucher's items (TOP_CHOICE: MYCHEW + premium), changing a CLAIMED voucher returns only the items no longer handed out, leaving CLAIMED returns them only with return_stock.
- POST `/api/admin/submissions/{id}/delete` `{reason,return_stock:false}` → `{ok:true}`. Deletes the play and its voucher (return_stock for a CLAIMED one), gives the try back, renumbers that person's remaining tries that day 1..n and rebuilds scores. Frozen halls are unchanged.
- GET `/api/admin/seeds` → `{items:[{id,strategy,tag,author,submitted_at}],count}`.
- POST `/api/admin/seeds` `{strategy,tag,author}` → `{id,count}`.
- POST `/api/admin/seeds/import` `{items:[{strategy,tag,author},...]}` OR `{csv:"l1,l2,l3,l4,l5,tag,author\n..."}` → `{imported,count}`. GET `/api/admin/seeds/export` → JSON `{items:[...]}`. No automatic seed generation.
- GET `/api/admin/inventory` → `{inventory:{MYCHEW:n,SESAME:n,ACE:n},counters:{mychew_used,premium_reserved},ledger:[]}`.
- POST `/api/admin/inventory/count` `{item:"MYCHEW"|"SESAME"|"ACE",count:integer,reason}` → same inventory response.
- GET `/api/admin/participants` → `{items:[{id,nickname,kind,name_hidden,submission_count}]}`.
- POST `/api/admin/participants/{id}/hide` `{reason}` → `{ok:true}`.
- POST `/api/admin/freeze` `{scope:"DAY1"|"DAY2"|"DAY3"|"OVERALL"}` → hall response. Must close day first; OVERALL requires day3 closed. Repeated calls return existing fixed result.
- GET `/api/admin/audit` → `{items:[{id,action,reason,details,at}]}` newest first, <=300.
- GET `/api/admin/export` → ZIP of CSV (no names, student IDs, tokens).
- GET `/api/admin/backup` → consistent anonymous JSON operational export (restore_supported:false). Full database backups require the supplied local backup script.
- GET `/api/admin/qr` → SVG QR for PUBLIC_BASE_URL or request origin.
- POST `/api/admin/purge` `{confirm:"PURGE",reason}` → `{ok:true,participants:n,backups_require_deletion:true}`. Deletes sessions, identifying fields and pseudonymizes all names including frozen rankings/cached responses; irreversible; booth closed.
- POST `/api/admin/reset` `{confirm:"RESET",reason}` → `{ok:true}`. Only before any operating day (1–3) has ever opened.

## Test mode (`day_no` 9)
- Select it with POST `/api/admin/day` `{day_no:9}` (current day must not be OPEN/PAUSED). `state`, `scoreboard` and `dashboard` report `test_mode:true`; `days[].is_test` marks it.
- Ignores date/sessions (open whenever the booth is OPEN). Needs a threshold only: no minimum seed count (the first test submission may have 0 opponents: win_rate 0, BASIC) and no physical stock and claims never write the inventory ledger.
- Pool = seeds + test submissions only; caps and counters count test entitlements only. Real days never see test submissions.
- Its threshold and day config stay editable after opening. Opening it does not lock seeds, RESET, or days 1–3. Visiting it never allows returning to an earlier real day. Not freezable; excluded from exports.
- POST `/api/admin/test/clear` `{}` → dashboard. Deletes test submissions, entitlements and thresholds, deletes guests who only played in test mode, and resets the test day to CLOSED.
